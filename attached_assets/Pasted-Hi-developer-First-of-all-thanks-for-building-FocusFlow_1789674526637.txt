Hi developer,

First of all, thanks for building FocusFlow. I really like the concept and the core blocking features work well for my use case (helping my child stay focused on study apps). However, I've run into several bugs specifically with the Focus Launcher feature that make it hard to use reliably. I'd like to report them in detail.

Bug 1: All apps in the Focus Launcher show the same generic icon
Description:
After enabling Focus Launcher, every allowed application is displayed with the same image/icon, which appears unrelated to the actual app. Because of this, it's impossible to tell which icon corresponds to which study app.

Expected behavior:
Each allowed application should display its own correct icon (or at least a distinguishable label/name), so the user can identify and launch the right app.

Impact:
My child cannot tell which app is which, which defeats the purpose of a clean launcher.

Bug 2: Clicking an app icon multiple times launches multiple instances
Description:
In the Focus Launcher interface, if I click the same app icon more than once, it starts a new instance of the application each time instead of bringing the already-running window to the foreground.

Expected behavior:
If the application is already running, clicking its icon should focus/switch to the existing window rather than launching a duplicate instance.

Impact:
Repeated clicks create multiple windows/processes, which is confusing and can consume extra system resources.

Bug 3: Focus Launcher can be exited by dismissing the PIN dialog and clicking Exit again
This is the most serious issue, since it allows the restricted user to bypass the lock.

Steps to reproduce:

Enable Focus Launcher (with PIN protection enabled).

Click the Exit button (bottom-right corner).

A PIN/password dialog appears.

Enter arbitrary/incorrect content in the PIN field until the Confirm button becomes visible, then click Confirm. (No valid PIN is entered.)

Click the Exit button again.

Focus Launcher exits successfully without requiring the PIN.

Expected behavior:
The Exit action should always require a correct PIN. Dismissing the dialog should not reset or bypass the verification state. Every exit attempt must re-trigger PIN validation, and an incorrect/empty PIN must never allow exit.

Impact:
This completely defeats the purpose of the PIN lock. Anyone (including my child) can exit Focus Launcher and regain full access to the desktop, which is exactly what I'm trying to prevent.

Environment
OS: Windows 10 (version: [22H2, build 19045])

FocusFlow version: [2.0.0.0]

Installed from: Microsoft Store

Nuclear Mode: [enabled]

User account type: [administrator]

Additional notes
I understand Focus Launcher may still be under development. These issues seem to be logic/UI bugs rather than configuration problems on my end. I've tried reinstalling and updating to the latest version, but the problems persist.

Could you please look into these? Bug 3 in particular makes the feature unusable for parental control purposes. Happy to provide more details, screenshots, or logs if helpful.

Thanks for your work on this.
